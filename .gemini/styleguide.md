# Java Spring Boot 팀 프로젝트 코드 리뷰 가이드라인

## 1. 기본 원칙 및 언어
* **언어**: 모든 리뷰와 피드백은 한국어로 작성한다.
* **어조**: 상호 존중을 바탕으로 건설적인 제안을 하며, "코드" 자체에 집중한다.
* **형식**: 문제점 설명 -> 이유(근거) -> 개선 제안(코드 스니펫 포함) 순으로 답변한다.

## 2. Java 및 Spring Boot 레이어별 준수 사항
* **Controller**:
  * 비즈니스 로직이 포함되지 않았는지 확인한다.
  * @Valid를 통한 입력 값 검증이 적절히 이루어졌는지 체크한다.
  * 엔티티(Entity)를 직접 반환하지 않고 반드시 DTO를 사용한다.
* **Service**:
  * `@Transactional`의 범위가 적절한지(읽기 전용에는 readOnly=true) 확인한다.
  * 하나의 메서드가 너무 비대하지 않은지, 단일 책임 원칙(SRP)을 지키는지 점검한다.
* **Repository (JPA)**:
  * N+1 문제가 발생할 가능성이 있는 곳에 `fetch join`이나 `EntityGraph`를 제안한다.
  * 불필요한 `save()` 호출이나 성능 저하를 유발하는 쿼리가 없는지 확인한다.
* **Domain & Entity**:
  * 비즈니스 로직을 도메인 모델 내로 캡슐화했는지(풍부한 도메인 모델) 확인한다.
  * Setter 사용을 지양하고 의미 있는 생성자나 정적 팩토리 메서드를 권장한다.

## 3. 공통 기술 이슈 및 클린 코드
* **예외 처리**: 
  * 단순히 `RuntimeException`을 던지지 않고, 비즈니스 의미가 담긴 커스텀 예외를 사용한다.
  * `try-catch`에서 예외를 삼키지 않고 적절히 로깅하거나 전파하는지 확인한다.
* **Optional 사용**: 
  * `Optional.get()`을 직접 호출하기보다 `orElseThrow()`나 `ifPresent()` 사용을 권장한다.
* **동시성 및 성능**:
  * 공유 자원에 대한 접근 시 멀티 스레드 환경을 고려했는지 확인한다.
  * 스트림(Stream) 사용 시 가독성과 성능의 균형을 체크한다.

## 4. 테스트 코드
* 테스트 명칭이 가독성 있게 작성되었는지 확인한다. (Given/When/Then 구조 권장)
* Edge Case(경계값, 예외 상황)에 대한 테스트가 포함되었는지 점검한다.
